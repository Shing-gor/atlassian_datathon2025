## The Business Problem

A SaaS company has a leaky bucket: it acquires new customers, but a silent segment churns before the business realises it is at risk. Simultaneously, a portion of its base is ready to expand — they just haven't been asked in the right way.

Without predictive signals, the sales and success teams treat every customer the same. The result: wasted retention spend on healthy customers, missed expansion revenue from ready upgraders, and churn that could have been prevented 30–60 days earlier.

**This project answers four questions:**

1. **Which customers are most likely to churn — and why?**
2. **Which customers are most likely to upgrade — and what triggers it?**
3. **How should the business allocate its acquisition budget across channels and industries?**
4. **How do we operationalise these insights so CSMs can act on them daily?** *(Downstream Optimization Layer)*

---

## Key Findings

| Finding | Business Impact |
|---|---|
| Three feature-usage signals (low seat utilisation, rising support tickets, billing gaps) predicted churn with **89% recall** | Enables proactive outreach 30–60 days before churn, preserving MRR |
| "Tech" and "Professional Services" industries showed 2.4× higher lifetime value and 40% lower churn than average | Acquisition budget should be concentrated in these verticals |
| 22% of the existing base met all upgrade criteria but had never been contacted | Represents a direct expansion revenue opportunity at near-zero acquisition cost |
| Month 4–6 is the critical "commitment window" — churn risk peaks then stabilises | Onboarding investment should be front-loaded into this window |
| A composite Account Health Score (0–100) across engagement + billing + feature signals segments accounts into AT-RISK / MODERATE / HEALTHY | CSMs can now prioritise outreach by score rather than gut feel |

## Methodology

### 1. Exploratory Data Analysis (`0_EDA.ipynb`)
- Profiled all four datasets for nulls, outliers, and structural issues
- Visualised MRR growth trends, acquisition cohorts, and the "leaky bucket" of new vs. churned customers across 18 months
- Identified segment-level differences by plan tier and industry

### 2. Acquisition Quality Analysis (`1_acquisition.ipynb`)
- Scored each acquisition channel by average LTV, churn rate, and upgrade likelihood
- Surfaced the channels producing disproportionate long-term value vs. short-term volume

### 3. Churn Prediction (`2_churning.ipynb`)
- Engineered features from billing, session, and event data (seat utilisation, support ticket trend, billing irregularities, feature depth score)
- Trained and evaluated a Random Forest classifier; tuned for recall to minimise missed churners
- Extracted SHAP-style feature importance to explain which signals matter most to the model

### 4. Upgrade Propensity Model (`3_upgrade.ipynb`)
- Defined upgrade-ready criteria from historical upgrade events
- Trained a second Random Forest model to score the current base on expansion likelihood
- Produced a prioritised list of accounts for the sales team to target

### 5. Downstream Optimization — GTM Intelligence Layer (`4_downstream_optimization.ipynb`) ✨

> *"The job is not to pull data. The job is to turn data into decisions."*

This notebook operationalises insights from analyses 1–4 into a SQL-driven CSM toolkit. It sits between the raw data and the Customer Success Managers — translating product signals into revenue decisions they can act on daily.

**Seven analysis modules:**

| Module | SQL Pattern | Revenue Question |
|---|---|---|
| **MRR Waterfall** | `LAG()` window function, `PARTITION BY` | Where is revenue growing vs. leaking? |
| **Account Health Score** | Multi-table `JOIN`, `CASE` weighted formula | Which accounts need intervention now? |
| **Churn Early Warning** | `ROW_NUMBER()`, MoM session decay | Who will churn in the next 30 days? |
| **Feature → Revenue** | Two-level aggregation, `HAVING` | What product behaviours drive expansion? |
| **Upsell Intelligence** | Business-rule `CASE` pipeline | Who is upgrade-ready today? |
| **Acquisition Channel ROI** | `RANK()`, risk-adjusted LTV | Which CAC dollar produces durable revenue? |
| **Tableau Export Layer** | Denormalised master view | Package everything for self-serve BI |

**Account Health Score Formula:**

```
Health Score (0–100) =
  Engagement Depth  (active months)    → up to 25 pts
+ Feature Breadth   (unique features)  → up to 25 pts
+ Billing Health    (zero overdue)     → up to 15 pts
+ Support Load      (low tickets)      → up to 10 pts
+ Revenue Signal    (average MRR)      → up to 25 pts
```

**Risk-Adjusted LTV Formula:**

```
risk_adj_ltv = avg_lifetime_mrr × (1 − churn_rate)
```

## SQL Patterns Reference

> For engineers and analysts extending the SQL library.

```sql
-- Pattern 1: LAG() for month-over-month revenue delta
LAG(total_mrr) OVER (PARTITION BY plan_tier ORDER BY month) AS prev_mrr

-- Pattern 2: CASE-weighted composite score with MIN/MAX clamp
MIN(100, MAX(0,
    CASE WHEN active_months >= 9 THEN 25 WHEN ... ELSE 0 END
  + CASE WHEN unique_features >= 6 THEN 25 WHEN ... ELSE 0 END
  + ...
)) AS health_score

-- Pattern 3: ROW_NUMBER() to avoid slow correlated subqueries (O(n²) → O(n log n))
ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY month DESC) AS month_rank

-- Pattern 4: Risk-adjusted LTV
ROUND(AVG(lifetime_mrr) * (1.0 - AVG(churned_90d)), 2) AS risk_adj_ltv

-- Pattern 5: RANK() for competitive channel ranking
RANK() OVER (ORDER BY risk_adj_ltv DESC) AS ltv_rank

-- Pattern 6: NULLIF guard against division by zero
SUM(mrr) / NULLIF(COUNT(DISTINCT user_id), 0) AS avg_per_user
```

## Setup & Reproduction

```bash
# Clone the repo
git clone https://github.com/Shing-gor/atlassian_datathon2025.git
cd atlassian_datathon2025

# Install dependencies
pip install -r requirements.txt

# Run notebooks in order
jupyter notebook

CREATE VIEW billing  AS SELECT * FROM read_csv_auto('data/billing.csv');

CREATE VIEW sessions AS SELECT * FROM read_csv_auto('data/sessions.csv');
```
